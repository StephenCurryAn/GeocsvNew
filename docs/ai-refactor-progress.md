# 自然语言分析接入实施记录

## 实施范围

1. 抽出共享 LLM 客户端，保留原有生成与修复接口。
2. 增加独立自然语言规划器：已验证算子优先，模型只返回计划，运行时校验图层、字段和能力，不生成执行代码。
3. 把助手与表单的任务轮询、结果读取、取消和展示收敛为共用逻辑。
4. 支持既有结果的图表追问；不创建新计算任务。
5. 验证歧义、超出能力、模型错误输出、旧入口兼容及真实 PostGIS 完整链路。

## 边界

本轮优先接入已验证的 `spatial_pivot@1`，能力仍是逐目标面计数及可选点类别拆分。不把缓冲、求和、过滤、排序或类别去重悄悄当作计数执行。自然语言返回计划后可审阅并提交，执行继续使用同一 Run 与 Artifact。

助手上下文只传执行记录 ID，服务器读取历史事实；不再在新流程中回传 Python 源码和表格样本。图表类型独立于计算参数，展示追问读取已有结果。

## 验证结果

已完成后端协议、规则与模型草案校验单元测试；真实 PostGIS 测试确认自然语言与表单产生同一协议，得到相同的 2、1、0 结果。规划、图表追问与不支持的需求都不增加运行记录。

浏览器已走通：勾选示例街道和设施 → 输入“统计每个街道内不同类型的设施数量，排除边界” → 检查计划 → 执行同一 Run 接口 → 得到统计表和地图。追问“把上次结果换成饼图”复用同一 Artifact；示例库运行记录数仅从 1 增加到 2，追问后保持 2。

在线模型解析使用了合成示例元数据测试，未发送实际业务属性或坐标。当前直连模型服务发生 `ECONNRESET`；通过系统现有代理复测也未完成 TLS 握手。模型通道的正常响应已通过注入测试覆盖，但当前环境的真实在线成功响应尚未验收。失败会转为明确的补充/重试提示，不创建任务，也不自动切到 Python。

验收截图：[复用结果的饼图与地图](screenshots/natural-analysis-reuse.png)。最终版本重载、恢复历史并切换图表后，未出现新的浏览器运行错误。

## 已整理的重复逻辑

- `server/src/integrations/llm/client.ts` 统一提供商、密钥、代理和客户端初始化；旧代码生成/修复功能继续使用原有接口与提示词。
- `analysisPlanner` 独立维护自然语言请求校验、能力匹配、歧义提示、结构化模型规划和草案校验。
- `useAnalysisRun` 共用运行创建、轮询、取消、历史恢复、分页、GeoJSON 与 CSV；`AnalysisRunView` 共用结果弹窗与状态展示。
- 独立的 `useRunHistoryStore` 同步表单与助手的运行目录，按状态进展合并迟到快照，终态不会倒退；当前选择与结果界面仍各自独立。
- 原 `SpatialPivotPanel` 只保留参数表单和计划检查；`UnifiedAnalysisAssistant` 只处理自然语言草案与结果引用。

## 当前能力与约束

`ready` 表示经过校验的待执行计划；`clarification` 表示需要补充；`unsupported` 表示无法完整映射到已验证算子；`view_only` 只引用已成功执行的结果。模型输出的 Python、SQL、未知版本、隐藏图层、缺失字段、额外条件与无效图表都不会执行。

本轮不会扩张 `spatial_pivot@1` 的算法范围。缓冲、过滤、求和、均值、密度和类别去重数量仍需后续验证并注册能力。原有三个实验模式保留，用户可显式切换；新流程不会自动降级。

自然语言对话上下文目前绑定一个明确的成功运行，可从共享历史选择。它不是通用长对话记忆；多个待确认分析仍需逐个审阅。

## 最终验证命令

- `server: npm run build`、`npm test`：编译与 10 项单元测试通过。
- `server: npm run test:integration`：独立真实 PostGIS 测试通过，涵盖自然语言与表单等价、规划不执行、结果追问不重算及原有故障恢复用例。
- `client: npm run test:analysis`、`npm run test:pipeline`：共享目录 3 项、流协议 6 项通过。
- 新增/迁移前端模块的定向 ESLint、前端 TypeScript 与生产构建通过；仍有单包体积警告。
- `git diff --check` 通过，原有已暂存改动未重置，旧功能未批量删除。

上述测试不等于在线模型服务已连通；真实在线成功响应仍受当前网络限制。未因测试修改现有 API 密钥、代理设置或 `.env`。
