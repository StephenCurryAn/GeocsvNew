# 02 前端加载优化

日期为 2026-11-16。基线提交为 `f314f6287aabd4c7ab12bf7e4a1c4b3e0d513e74`，模块分支为 `codex/02-client-loading`。

## 入手依据与范围

生产入口从 `main.tsx` 进入 `App.tsx`，再静态导入 `DataPivot` 和 `SplitTablePanel`。基线中两处都导入了 AG Grid 运行时和两份主题相关 CSS，也各注册了一次社区模块。无文件数据时属性表只渲染提示，透视面板有结果时才渲染网格，但基线构建清单只有一个入口 JS 和一份入口 CSS，AG Grid 随首屏传输。

本批次把两个网格用到的同一份 AG Grid 运行时和样式设为按需加载。表格选项、数据请求和业务回调沿用原实现。依赖锁、分析提交、底图控制器和后端均未改动。

## 实现与学习

- `TableGrid.tsx` 汇集 AG Grid 的运行时导入、样式和模块注册。`DataPivot.tsx` 与 `SplitTablePanel.tsx` 仅保留类型导入及对 `DeferredGrid` 的引用。TypeScript 会擦除类型导入，因此它们不会在构建产物中产生静态依赖。
- `DeferredGrid.tsx` 在两个表格实际渲染网格的位置使用同一个 `React.lazy`，并转发原网格的引用。Vite 把动态导入的 JS 和 CSS 放到独立资源中。等待时由 `Suspense` 在网格区域显示加载提示。加载失败时，错误边界留住页面其余区域，并提供“刷新页面”以重新加载入口和资源。
- 属性表继续监听地图选中变化，同一段同步逻辑也在网格首次渲染数据时执行。这样即使用户在资源下载期间点击地图要素，表格就绪后也能按原有的 ID 或名称匹配规则选中对应行。

- `npm --prefix client run test:analysis` 通过 3 项，`npm --prefix client run test:pipeline` 通过 6 项，`npm --prefix client run test:basemaps` 通过 9 项。生产构建和 `git diff --check` 通过。
- 使用 `npm --prefix client run preview -- --host 127.0.0.1 --port 5174 --strictPort` 预览生产构建。用 Playwright 1.65.1 驱动 Chrome 157，文件树、单点分页数据、CARTO 瓦片、业务矢量瓦片和透视结果均由浏览器拦截并返回样例。没有使用真实密钥，也没有向后端提交计算或写入。
- 冷启动显示属性表空态，表格 JS 和 CSS 请求均为 0。选中文件后各请求 1 次，故意延迟 CSS 时表格显示加载提示。延迟期间点击地图样例点，CSS 返回后表格渲染并选中对应行。取消选择再打开属性表，以及打开样例透视结果，均没有新增表格资源请求。
- 在独立浏览器会话中分别阻断表格 JS、CSS。两次均只在表格区域显示错误，地图和文件树仍可见。解除阻断后点击“刷新页面”，重新选择文件，浏览器重新请求资源且表格恢复。刷新会重新初始化页面，需要重新选择图层。
- Vite 的大包提示仍在。首开表格仍需下载独立的 AG Grid 资源。本次测量了产物体积与资源触发时机，未测量真实网络下的页面耗时，也未执行真实后端计算。
