# GeoCSV 并行会话与分支约定

日期：2026-11-16。各会话归属 Codex 的 GeoCSV 项目。

## 命名与隔离

- 会话：两位编号 + 中文模块名，例如 `01 Python算子基线`。
- 分支：`codex/NN-english-module`，编号与会话对应。
- 公共基础：`codex/00-foundation`，由原 `agent-refactor` 分支更名，保存环境、通用修复与底图接入。历史文档中的旧分支名描述当时基线。
- 模块工作目录：`D:/GeoCSV/.worktrees/NN-english-module`，用 Git worktree 隔离文件与分支，父目录已忽略，不复制真实密钥。
- 所有新分支从已提交的公共基础创建。每个会话使用自己的工作目录；不能在 `D:/GeoCSV` 根工作目录切分支或编辑公共文件。

## 主会话保留的架构工作

阶段 1 的分析协议、幂等提交与数据库迁移由主会话统筹，再发布稳定契约。阶段 2 的统一 Python 执行接口依赖该契约；阶段 3/4 的 LangChain、LangGraph 正式接入依赖可信工具与任务协议，不能因并行开发跳过这些依赖。deck.gl 性能试点按原计划推进，不包含在 02 的首屏加载小批次。

## 合入流程

1. 模块会话先审阅基础文档，报告小批次计划，再实现并验证；解释具体代码和学习要点。
2. 使用独立依赖目录与端口。不要结束主工作区 3000/5173/8000 上的服务；02 如需页面验证使用 5174，01 本轮优先离线测试，无需数据库和密钥。
3. 完成后在自己的分支提交，汇报提交 ID、变更范围、验证证据和限制；不自动 push、合并、重写历史或清理工作目录。
4. 主会话审阅实际差异与依赖，再按依赖顺序整合。公共接口变化先落共同契约，依赖模块同步后继续。
5. 合入后运行受影响的集成检查；通过后再推送整合分支。公共基础与模块完成状态分别记录，不以“已创建会话”代替“已完成改造”。
